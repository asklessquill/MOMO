# SARU — 「Systemの余白」改定メモ

Status: **PROPOSAL / NON-AUTHORITATIVE / NO CURRENT-STATE EFFECT**

Date: 2026-09-16

Source: Human discussion / concept note

## 1. Purpose of this memo

この文書は、MOMO System v0.5 の現行責任モデルを変更するものではない。

現行 v0.5 における SARU は `Human World Activation, operation and bounded reality experimentation` を担うが、Human から、将来の改定候補として別の中心概念が提示された。

その候補は、SARU を **桃多郎Systemの「余白」** として位置付けることである。

## 2. Proposed center of meaning

SARU の中心テーマは、目的・分類・帰属を先に固定することではなく、

> **とにかく、やってみる。**

ことである。

アイデアを実際に試し、結果を見る。

試行は外向けでも内向けでもよい。桃多郎System自身に関係する必要もない。

既存Systemの設計・分類・工程に必要に応じて準拠してよい一方、それらを前提にしない試行も許容する。

## 3. Why SARU exists

成熟したSystemは、既存の意味体系・責任境界・合理性に沿って判断するほど、そこから外れる可能性を捨てやすくなる。

SARU は、その固定観念を破るための構造的な余白を残す。

SARU は、まだ「何のためか」「どこに属するか」「正式に作る価値があるか」が決まっていないものでも、まず試せる場所である。

失敗や不採用も正当な結果であり、試行開始時点で桃多郎Systemへの寄与を要求しない。

## 4. Possible destinations of a SARU trial

SARU の試行結果は、あらかじめ一つの出口へ拘束しない。

結果として、例えば次のいずれにもなり得る。

- 桃多郎Systemへ知見・Capabilityとして還元される
- KIJI の新しい観測・研究対象になる
- INNU の正式な Product / Capability Task になる
- 独立した新Projectへ発展する
- 単発の便利な試行としてその場で完結する
- 有用性がなく破棄される
- 当初想定していなかった別の可能性を開く

**Systemへの昇格・還元は optional であり、試行成功から自動的に発生しない。**

## 5. Relationship to FROG / SandFrog

この候補定義では、旧FROGの `Make it real enough to learn` は SARU の内部Capability / stance として自然に位置付けられる。

- FROG: 「考え続けるより、学べるだけの現実を作る」Reality Mentor capability
- SandFrog: 壊してもよい、置換可能な experimental substrate

どちらも SARU とは別の責任Actorを構成しない。

## 6. Applicability beyond current Momotaro

この「余白」という役割は、将来の派生Systemにも適用できる可能性がある。

### 汎用特化 桃多郎

広い目的・Capabilityを持つSystemであっても、既存分類に入らない発想を試す余白を保持する。

### 専用特化 金太郎

特定目的へ深く最適化されたSystemほど局所最適へ閉じやすいため、本来の専門領域から少し外れた試行を許す余白が重要になる。

したがって候補原則は、次のように一般化できる。

> **SpecializationしてもExplorationを殺さない。**

## 7. Short expression candidate

候補となる最小表現:

> **SARU — Systemの余白。既存の目的・分類・設計に縛られず、まず試し、そこから生まれた可能性を次の行き先へ渡す。**

あるいは、より短く:

> **SARU = Try / やってみる**

これは `KIJI = Know / 知る`、`INNU = Build / 作る` と並ぶ将来候補であり、現行定義ではない。

## 8. Authority boundary

このメモは **proposal** である。

- MOMO System v0.5 の Current を変更しない
- SARU の現行責任・HUMAN_GATE / STOP を変更しない
- FROG / SandFrog の現行 disposition を変更しない
- 新しいTask、実験、外部Action、実装、移行を開始しない
- 将来 Current に採用するには、別途 Human authority と必要な semantic revision / review / acceptance を要する

MOMO System v0.5 の現行正本と矛盾する場合、Current が優先する。
