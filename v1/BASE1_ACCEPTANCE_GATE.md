## 1. Meaning

v0.5 answered:

> **桃多郎とは何者か。**

Base-1 must answer:

> **桃多郎は本当に働けるか。**

Base-1 is the minimum evolvable common ancestor from which both a Generalist MOMOTARO line and a Specialist KINTARO line may later diverge.

Base-1 is not a new Actor model and is not an architecture-expansion phase. It is an end-to-end execution proof using the existing v0.5 responsibility model.

The Current constitutional model remains `MOMO SYSTEM v0.5 CLOSED / CURRENT / RECOVERABLE / STOP` until a later Human-authorized acceptance changes Current.

## 2. Existing responsibility model is fixed input

Exactly five responsibility-bearing Actors remain:

- MOMO — System meaning, reusable System knowledge, Human-facing views and constitutional provenance.
- KIBI — semantic connection Protocol.
- KIJI — World observation/evidence/interpretation through implementable Requirements.
- INNU — accepted Product/Capability realization and completion, including model/tool mastery.
- SARU — Human World Activation, operation and bounded reality experimentation within current Human authority.

Human remains outside the Actor count and is the final source of Purpose, constitutional authority and bounded external-action authority.

No additional Actor is authorized by Base-1.

## 3. Three interpretation constraints

### KIBI is cross-cutting, not a process step

Do not model KIBI as a serial worker between KIJI, INNU and SARU.

KIBI defines semantic boundaries and connection contracts across the loop. It does not choose Tasks, orchestrate work, or own Application internals.

### MOMO is not a work-log sink

Reality evidence does not automatically update MOMO Current.

Evidence first returns to the responsible owner/Application. MOMO Current changes only when System-wide meaning, responsibility, authority, recovery precedence or other genuinely Current System meaning changes.

### Git is durable recorded state/evidence, not external Reality itself

Git may durably record observation, provenance, acceptance and evidence. A Git record that says SARU changed Reality is not by itself proof that external Reality still has that state.

Where external-world truth matters, observation of Reality and durable recording of that observation must remain distinguishable.

## 4. Base-1 execution loop

One bounded cycle must prove the following without Human acting as transport between Applications:

1. Human provides one Purpose and bounded Authority.
2. A fresh System recovers Current durable state.
3. KIJI produces an evidence-backed implementable Requirement.
4. INNU realizes the required Capability/Product.
5. Independent verification/acceptance establishes that the Capability is fit for the bounded purpose.
6. SARU performs one explicitly authorized, reversible/bounded real-world Action where required.
7. The resulting external state/result is observed.
8. Evidence and learning are durably recorded by the responsible owner(s).
9. System-wide Current is updated only if the evidence truly changes System-wide Current meaning.
10. A Fresh Actor can recover the resulting state from durable sources.
11. Mockpit lets a Human joining mid-cycle understand the current stage, owner, gate, evidence and source within seconds.
12. The cycle reaches a durable STOP.

Human Gates are not failures. Human transport/relay is the failure mode to eliminate.

## 5. Human relay invariant

After the initial Purpose + bounded Authority is given, the Human must not be required to relay artifacts such as:

- copying KIJI output into INNU;
- manually reconstructing repository/current state;
- carrying build results to SARU;
- manually assembling evidence for recovery;
- explaining to Mockpit what stage the System is in.

A Human decision or approval that is genuinely reserved to Human authority is allowed and expected.

## 6. Mockpit acceptance role

Mockpit is observability across the loop, not an Actor and not an orchestrator.

For Base-1, Mockpit must make progression legible, such as:

`Purpose → Researching → Requirement Ready → Building → Review → Accepted → Human Gate → Activated → Observing Result → Learned → STOP`

The exact labels may differ if source-backed semantics require it.

The acceptance criterion is not visual polish. It is whether a Human can join mid-cycle and understand within seconds:

- what Purpose is being served;
- current stage/status;
- responsible owner;
- whether a Human Gate exists;
- what evidence supports the status;
- which durable source is authoritative;
- what is UNKNOWN/STALE/UNAVAILABLE.

Mockpit remains read-only Observe/Explain unless separately authorized later.

## 7. Base-1 PASS criteria

Base-1 PASS requires evidence that:

- one bounded Purpose reached a durable STOP through the full execution loop;
- KIJI Requirement, INNU accepted Capability and SARU authorized Action are distinguishable and linked;
- KIBI boundaries held without becoming orchestration;
- no hidden sixth Actor emerged;
- Human was not used as transport/relay;
- required Human Gates were preserved rather than bypassed;
- external Reality and Git-recorded evidence were not conflated;
- evidence ownership and provenance are recoverable;
- a Fresh Actor can recover post-cycle state without Builder chat context;
- Mockpit can explain mid-cycle/current state from source-backed observation;
- no unbounded authority, automatic retry, next Task or autonomous external mutation is inferred from completion.

A single successful path is not enough if it depends on undocumented Human relay or Builder memory.

## 8. First-cycle selection constraints

The first Base-1 task should be deliberately small.

Prefer a task that is:

- objectively measurable;
- reversible or low-cost to undo;
- safe and bounded;
- capable of reaching an actual external Action and observed result;
- feasible with existing capabilities where possible;
- rich enough to exercise KIJI → INNU → SARU responsibility transfer;
- not dependent on adding a new Actor or redesigning the Constitution.

Do not choose a difficult domain merely to make the demonstration impressive.

## 9. Evolution after Base-1

Only after Base-1 PASS may a later Human decision establish divergent evolution lines such as:

- **MOMOTARO / Generalist** — maximize adaptation to unknown Purpose through capability discovery, composition, Build/Buy/Borrow/Reuse and reusable creation.
- **KINTARO / Specialist** — maximize measurable outcomes inside a bounded domain through deep data, models, tools, knowledge and operating practice.

Base-1 should remain stable. A capability discovered in either line does not automatically return to Base.

Possible classification of learned capability/evidence:

- Base inherited;
- MOMOTARO-specific;
- KINTARO-specific;
- candidate for Base.

Promotion to Base requires later evidence of generality and separate authority; convenience in one branch is insufficient.
